# Moj Elektro 0.3.0 beta test checklist

Use this checklist when testing **0.3.0-beta.1** (or a newer 0.3.0 prerelease from the development branch) in a real Home Assistant installation.

> [!WARNING]
> 0.3.0 is still a development version. Create a Home Assistant backup before replacing 0.2.7.

## 1. Upgrade safety

- Start from the maintained fork 0.2.7 with an existing Moj Elektro config entry.
- Record several existing entity IDs before the upgrade.
- Install the 0.3.0 development build without deleting the integration or config entry.
- Restart Home Assistant.
- Confirm the existing entity IDs remain unchanged.
- Confirm dashboards and automations referencing old entities still resolve.
- Confirm no duplicate Moj Elektro entities were created.

## 2. Startup and logs

- Open **Settings → System → Logs**.
- Confirm there are no Moj Elektro exceptions.
- Confirm there are no event-loop blocking-call warnings.
- Confirm there are no device-registry model warnings.
- Confirm no config-entry migration or reauthentication errors appear.

## 3. Configure / Options

Open **Settings → Devices & services → Moj Elektro → Configure** and verify:

- decimal places
- polling interval (5–1440 minutes; default 60)
- 15-minute lookback window
- enable/disable latest 15-minute readings
- enable/disable daily/monthly readings
- enable/disable cumulative total registers
- enable/disable tariff-block calculation
- enable/disable contracted-power sensors
- enable/disable privacy-safe souporaba summary
- stale-data threshold (24–168 hours; default 48)
- optional advanced reading types populated from the live /reading-type catalogue

Save a change and confirm the integration reloads successfully.

## 4. Data freshness

- Confirm **Last published reading** exists as a diagnostic timestamp sensor.
- Compare its timestamp with the newest data visible in Moj Elektro.
- Press the **Refresh data** button.
- Confirm the coordinator refreshes immediately.
- When the source timestamp exceeds the configured threshold, confirm **Data stale** reports a problem.
- Confirm it returns to normal when newer source data arrives.

## 5. Energy sensors

Check the following where data is available:

- latest 15-minute import/export
- daily import/export
- monthly import/export
- peak/off-peak daily and monthly values
- cumulative total import/export registers
- tariff-block daily import sensors
- contracted power blocks 1–5

Important checks:

- empty or partial Moj Elektro responses must not create false zero values
- 15-minute values should use the newest actually published reading, not the current wall-clock quarter
- daily/monthly values should remain correct across a month boundary
- cumulative total registers should be suitable for Home Assistant Energy Dashboard selection
- tariff-block totals should represent only the latest complete day

## 6. Energy Dashboard / statistics

- Open **Settings → Dashboards → Energy**.
- Confirm cumulative total import/export sensors are eligible where Home Assistant allows them.
- Add the desired total register temporarily if appropriate.
- After statistics are generated, confirm there are no false reset/rebound spikes.
- Confirm daily/monthly interval sensors do not behave like monotonic lifetime meters.

## 7. Reading quality

For sensors with source metadata:

- inspect entity attributes
- confirm source_timestamp is present when available
- confirm quality_flags_present is false when no quality flags are returned
- if Moj Elektro marks a reading, confirm reading_qualities exposes code/description
- confirm a flagged reading is not blindly discarded unless the API semantics explicitly require it

## 8. Advanced reading types

If optional registers are available:

- select one or more in Configure
- reload the integration
- confirm one entity is created per selected semantic tag
- confirm names come from the live Moj Elektro catalogue
- confirm deselecting a register stops loading it after reload
- confirm selecting built-in A+/A- tags does not create duplicate built-in entities

## 9. Souporaba privacy

If souporaba is enabled:

- confirm only status counts are exposed as entities
- confirm EIMM, GSRN, names, addresses and contact details are not exposed in entity states/attributes
- confirm a souporaba endpoint failure does not break ordinary meter sensors

## 10. Reauthentication

Only test this when convenient:

- use an invalid/expired token
- confirm Home Assistant requests reauthentication
- enter a valid replacement token
- confirm the existing config entry reloads without removing/recreating entities

## 11. Diagnostics privacy

Download diagnostics from the Moj Elektro integration.

Confirm the file contains useful technical/support metadata, but does **not** contain:

- API token
- EIMM
- meter measurement values
- owner/contact data
- address
- meter serial number

## 12. Report useful evidence

For any problem, capture:

- Home Assistant version
- integration version / branch commit
- relevant log lines
- affected entity ID
- whether manual Refresh reproduces the problem
- diagnostics file, after quickly checking it contains no unexpected personal data

Never include the Moj Elektro API token in an issue.
